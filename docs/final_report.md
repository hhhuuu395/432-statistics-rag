# 收官报告：一次评测驱动的 RAG 迭代

> **阅读对象**：AI 产品 / 算法岗面试官
> **配套**：[docs/experiments.md](experiments.md)（逐阶段实验记录）、[README.md](../README.md)（架构与运行）、仓库 commit 历史

---

## 一页速览（3 分钟看懂）

**我做了什么**：给中南大学 432 统计学考研场景做一个知识点答疑 RAG 助手，语料是老师的教材笔记、历年真题、模拟卷，评测集是 **282 条真实师生答疑记录**。

**我的做法**：没有一次把系统搭"完整"，而是走了一条**评测驱动**的路线 ——

> 先跑最朴素的链路拿基线 → 用 badcase 归因定位瓶颈 → **每次只改一个地方** → 用评测数据决定这个改动留不留。

**结果**：

| | 基线 | 四级后 |
| --- | --- | --- |
| 统计专业课 答案准确率 | 16.7% | **35.7%**（相对 +114%） |
| 数学基础 答案准确率 | 4.9% | **24.2%** |

**改动的因果链**（每一环都由前一轮的 badcase 数据触发）：

```
基线 16.7%
   │  badcase 归因：语料缺失 52%       ← 茆书教材是扫描版，没进语料
   ▼
OCR 茆诗松教材前 6 章 → 26.4%
   │  badcase 归因：检索未召回 22%
   ▼
上混合检索（BM25 + reranker + RRF）→ 26.4%（持平）
   │  badcase 归因：prompt 没压住 80%  ← 检索到对了，是生成没用上
   ▼
改 prompt（3 处）→ 35.7%
```

**这个作品集最想展示的一点**：第 2 级（混合检索）我加了 BM25 + reranker + RRF 一整套「看起来更高级」的检索组件，评测**一分没涨**。按「用数据证明有效再留」的既定原则，我把它如实记为**「未验证出净收益」**，而不是找个理由论证它有用。同样地，本报告下方用一整节写**已知局限**，包括我自己的评测指标不可复现的问题。**能诚实地报告自己方案的无效处，比多做两个功能更能说明问题。**

## 1. 问题与约束

| 项 | 内容 |
| --- | --- |
| 场景 | 考研 432 统计学专业课答疑，学生问题以微信截图形式沉淀 |
| 目标 | 答得有依据、可溯源（标注引用来源），降低老师的重复答疑工作量 |
| 硬约束 | 学生 PII 必须脱敏；教材 PDF 有版权、不能入库；MVP 不做 Web/部署 |
| 评测集 | 282 条真实答疑（统计专业课 129 / 数学基础 153） |
| 关键设计决策 | ① **分层评测**（数学基础 vs 统计专业课分开评）② **确认型 / 答案缺失不进主指标** ③ 每个改动都要有评测数据支撑 |

**为什么必须分层**：统计教材对纯数三数学题毫无帮助。混在一起评，数学基础会严重拖低总分，掩盖统计专业课的真实进步。这个决定在基线阶段就由数据确认：数学基础 4.9%（检索几乎无用），统计专业课 16.7%。

## 2. 四级优化曲线

| 阶段 | 改动 | 统计专业课 | 数学基础 | 归因依据（badcase） | commit |
| --- | --- | --- | --- | --- | --- |
| **基线** | dense 检索（BGE-M3 + FAISS），语料仅文本版源 1146 块 | 16.7%<br>相关性 1.60 | 4.9%<br>1.21 | — | `dc9873d` |
| **第 1 级：茆书 OCR** | 茆诗松教材前 6 章 313 页 OCR 入索引（1146 → 2335 块） | 26.4%<br>1.67 | 8.5%<br>1.18 | 失败样本中**语料缺失占 52%** | `d7807ec` |
| **第 2 级：混合检索** | dense + BM25 + RRF 融合 + BGE-reranker 重排 | 26.4%<br>1.78 | 10.1%<br>1.32 | 失败样本中**检索未召回占 22%** | `50b54cb` |
| **第 3 级：prompt 优化** | 3 处改动（见下） | **35.7%**<br>1.71 | **24.2%**<br>1.28 | 生成失败样本中**prompt 没压住占 80%** | `fff11f5` |

> 相关性命中率取值 1–3（3=充分 / 2=部分 / 1=不足）。第 3 级相关性微降 1.78→1.71 属**裁判噪声**，见 §5 局限一。

### 第 1 级：茆书 OCR —— 相对 +58%

- **数据说了什么**：第一轮 badcase 归因（30 条分层抽样，失败样本 27 条）显示 **语料缺失占 52%**，是最大瓶颈；且集中在分布函数定义、样本方差 n/n−1、极坐标变换等 —— 全部对应茆书第 1–6 章。
- **改了什么**：用多模态 LLM 逐页 OCR 茆书前 6 章（313 页、53.4 万字、0 空页），清洗水印与乱码后入索引，块数 1146 → 2335。OCR 公式质量经人工验算抽查（配对问题容斥公式、超几何分布、CLT 应用、表格行列加总自洽）。
- **结果**：统计专业课 16.7% → 26.4%。**这是四级里单步收益最大的一次改动**，因为瓶颈确实是"该有的知识根本不在语料里"。

### 第 2 级：混合检索 —— 持平（如实记录为「未验证出净收益」）

- **数据说了什么**：第二轮 badcase 显示「检索未召回」占 22%（检索到了相关块，但没进 top-k）。据此上了 dense + BM25 + RRF + BGE-reranker 的全套混合检索。
- **结果**：统计专业课 **26.4%，与上一级完全持平**；只有平均相关性小升（1.67 → 1.78）。
- **我的判断**：持平有两种可能 —— ① 检索确实打透了，② 组件没有增益。无论哪种，按项目既定原则「每个增强都要用评测数据证明有效再留」，这一级**记作未验证出净收益**，reranker 保留为可回退项（回退 dense-only 更简单）。它真正的价值是**排除了「检索还有余量」这个假设**，从而把注意力推到生成环节。

### 第 3 级：prompt 优化 —— 相对 +35%

- **数据说了什么**：第三轮 badcase 只看「检索相关性 ≥ 2 但答案仍然错」的生成失败样本（10 条），归因 **prompt 没压住 80%**、该换更强模型仅 10%。典型症状：检索到了相关内容，模型却说"资料不足"；答非所问（没理解"这个题/这一步"的指代）；答反/漏要点。
- **改了什么**（3 处，唯一变量就是 prompt）：
  1. 弱化兜底指令：「若资料不足就说资料不足」→「基于资料尽力回答……只有资料与问题完全无关时才说明资料不足」。
  2. 新增「直接简洁，先给结论再简要解释」。
  3. 新增「简短/含指代的问题结合资料块推断所指」。
- **结果**：统计专业课 26.4% → **35.7%**，数学基础 10.1% → **24.2%**，且**涨分覆盖 8 个章节中的 7 个**，不是单章侥幸。
- **反直觉之处**：涨得最多的不是统计专业课，而是**数学基础（+14.1pp）**。原因是该层检索相关性只有约 1.3（≈「不足」），旧 prompt 下模型频繁回"资料不足"；新 prompt 允许它用自身数学知识作答，于是把原本就有的能力释放了出来。**这直接引出了 future work 的分层策略。**

### 附：改动 3 的风险验证（编造率 A/B）

改 prompt 有一个明确风险：弱化"资料不足"指令，可能让模型**资料不够也硬答**（矫枉过正）。我用 A/B 实验专门验证，而不靠感觉：

| 层 | 旧 prompt 编造率 | 新 prompt 编造率 | 净变化 | 双向翻转 |
| --- | --- | --- | --- | --- |
| 统计专业课 | 18/30 = 60% | 17/30 = 57% | −1 | 7 条 无→有 / 8 条 有→无 |
| 数学基础 | 17/30 = 57% | 17/30 = 57% | **0** | **5 / 5 完全对称** |

**结论：改动未矫枉过正。** 判据不是"数字好看"，而是**是否出现单向迁移** —— 若改动诱导模型硬答，应观察到大量「无编造 → 有编造」；实际两层都是双向对半。尤其涨幅最大的数学层，翻转完全对称。

## 3. badcase 的产品视角分析

> 上面两节看的是分数和方法。这一节把同一批 badcase 换回**学习者的视角**讲一遍：学生当时问了什么、拿到什么、被误导在哪、改完之后体验变成什么样。
> 案例与回答原文全部取自既有归档（`data/badcase_analysis.json`、`data/badcase_gen.json`、`data/ab_fabrication.json`）与 `data/report.json`，未新增数据。

### 案例一 · 答得头头是道，答的却是另一道题

**学生问**：「圣才的题目上有些方差按 n−1 算有些按 n 算是为什么呀」

**这句话背后的处境**：他在刷题时发现同一个"方差"符号在不同题里除以不同的数——有的除 n、有的除 n−1。他困惑的是**一个符号的用法**，要的是一句能对上号的口径。

**系统当时给的回答**（基线轮，原文）：
> 「同学，这个问题要先分清：题目里说的"方差"到底是哪一个统计量。根据现有资料，可以确定的是——**方差分析中的均方不是一律按 n 或 n−1 算，而是按对应平方和的自由度来算**……总平方和 SST 的自由度是 n−1……」

**他受到的伤害**：整段回答在讲方差分析的均方与自由度，**和他问的不是同一件事**——但他不容易看出来，因为回答条理清楚、带 [来源2][来源6] 引用，看上去比老师那句"除 n 就行"更"专业"。**带引用的错误答案比"我不知道"更容易被当成知识记下来**；照这个理解去刷题，错的是他对整个章节的记忆。

**哪一轮修的**：第一轮 badcase 归因把这题判为**语料缺失**（该归因占失败样本 52%，是当时最大的瓶颈）。原因很具体：老师讲这个点依托的茆诗松教材是纯扫描 PDF，根本没进语料。第 1 级把茆书前 6 章 OCR 入索引后，同题判级从「错」升到「半对」，回答也改口引上了「茆诗松教材明确说：以后讲样本方差通常指的是 s²，其偏差平方和……的自由度是 n−1[来源1]」。该题所在章节（参数估计，n=12）基线 13% → 最终 37.5%。

**一句话产品认知**：**对学习者，错误答案比没有答案伤害更大**——学生没有甄别能力，而"看起来很专业"的错答恰恰最难被质疑。

### 案例二 · 它其实会做，却被自己那句"资料不足"挡住了

**学生问**：「（发题目图片）设 X₁,…,Xₙ 是来自正态总体 N(μ,σ²) 的样本，证明样本均值与样本方差相互独立。」

**这句话背后的处境**：一道考研高频证明题。他要的不是"结论是什么"，而是"怎么证"——拆成 r 组协方差那套写法。

**系统当时给的回答**（第二轮归因抽样中的原文）：
> 「严格按所给资料，**完整证明的资料不足**：资料中只给出了结论和证明提示，没有展开完整的正交变换证明步骤。现有资料能支持如下内容：1. 结论在资料中是明确的：'正态总体下样本均值与样本方差相互独立'[来源2]……」

**他受到的伤害**：他要证法，拿到的是"资料不足"加一段他早就知道的结论。**真正的损失不是这一次没答上，而是他不会再问第二次**——试两次就会给助手贴上"只会念资料"的标签，之后有问题直接去找老师，答疑工作量一点没减。

**哪一轮修的**：第二轮归因里，这类"检索到了相关内容、模型却答不出"的失败有 **80% 判为 prompt 没压住**（这道证明题被归进另外 10% 的"该换更强模型"）。第 3 级没有换模型，只把"资料不足就明说"弱化成"只有资料与问题完全无关时才说明资料不足"。整层的效果：数学基础 4.9% → 24.2%，而该层检索相关性始终只有 1.28（≈不足）——**这一大块涨幅来自"模型自身已有的能力被放出来"，不是检索变好了**。该题所属章节（统计量及其分布，n=17）也从基线 15% 升到最终 41.2%。（最终轮只留存了逐题判分、没有留存生成回答，所以这里给到的是章节级前后对比；"保存生成答案"已列入 future work。）

**一句话产品认知**：**"宁可不答也别答错"的兜底直觉，会在语料不全时把模型已有的能力一并关掉**——安全话术的代价不是少答一道题，是学生不再来问。

### 案例三 · 改完之后，它不再说"不能编造"了

**学生问**：「请问假设检验的显著性水平和真实水平是什么呀？」

**这句话背后的处境**：复习时最容易混的一对概念——一个是自己事先定的，一个是算出来的。他要的是一句能区分两者的判据。

**旧 prompt 下的回答**（第二轮归因抽样中的原文）：
> 「同学你好，先说明：你给的资料里没有直接出现"真实水平"这个术语的明确定义。若题目原文就是"真实水平"，则**资料不足，不能硬编**。……」

**他受到的伤害**：他问的是概念，拿到的是"我们资料里没这个词"。**这句保守话术并没有解决他的困惑，只是把问题原样退回去了**——他要么再问一遍，要么带着没解开的疑问上考场。

**改完之后的另一面**：这题的检索相关性是 3（充分），本来不缺资料。改 prompt 之后，它在编造 A/B 实验里从**「无编造」翻成「有编造」**——30 条里出现这个方向翻转的有 7 条，它是其中之一。也就是说，**同一个 prompt 改动，在案例二里救回了整层能力，在这道题上却把"保守但没用的答案"换成了"更自信但缺依据的答案"**。这个取舍靠措辞买不齐。

**一句话产品认知**：**"不许编造"与"不许拒答"在 prompt 层是互相拉扯的；这类题的正解在语料覆盖，不在措辞**——假设检验恰好是茆书里唯一没 OCR 的章节（第 7 章，基线 55.6%，n=9）。

### 从三个案例提炼的两条产品原则

1. **给学习者的产品，错误答案比没有答案伤害更大。** 学生没有甄别能力，而带引用的错答因为"看起来专业"反而更容易被固化成知识。所以在这个场景里，"敢答"必须排在"答得准"后面——不能为了答题率牺牲可信度。
2. **兜底话术是隐含的产品决策，不是工程细节。** "资料不足就说资料不足"写得越安全，被挡掉的模型能力越多（案例二：一层 +19.3pp）；写得越放开，编造风险越高（案例三）。这个取舍无法在一个 prompt 里两全，最终要靠**扩大语料覆盖**化解——这也正是 prompt 优化被记作"第 3 级"而不是终点的原因。

## 4. 方法：每一步改什么，是数据说的

两轮 badcase 归因的分布，直接决定了四级曲线的走向：

**第一轮**（30 条分层抽样，聚焦"答案错 / 相关性低"，失败样本 27 条）：

| 归因 | 占比 |
| --- | --- |
| 语料缺失 | **52%** |
| 生成没用好 | 22% |
| 检索未召回 | 22% |
| judge 误判 | 4% |

→ 指向第 1 级（OCR 茆书）与第 2 级（混合检索）。

**第二轮**（35 样本，只取"相关性 ≥ 2 但答案错"的生成失败 10 条）：

| 归因 | 占比 |
| --- | --- |
| prompt 没压住 | **80%** |
| 该换更强模型 | 10% |
| judge 误判 | 10% |

→ 指向第 3 级（改 prompt 而非换模型）。**这轮数据挡住了一次错误的动作**：直觉会想"答不好就换更强的模型"，但归因显示只有 1/10 需要更强模型，换模型是花钱不解决问题。

## 5. 已知局限（写透，不遮掩）

### 局限一：LLM 裁判有不可复现的噪声地板 ≈ 0.05–0.12

- **现象**：`judge_relevance` 的输入（学生问题 + 检索块）在两轮评测之间**完全相同**（检索链路确定性：BGE-M3 嵌入、BM25、reranker 均无随机性），但平均相关性仍从 1.78 → 1.71、1.32 → 1.28。分章节看更明显：有的章节完全不变（方差分析与回归 2.27、统计量 1.35），有的明显漂移（多维随机变量 1.61 → 1.48）。
- **含义**：即使 `temperature=0`，LLM 裁判的输出也不可复现。同一个裁判还负责判「对 / 半对 / 错」，因此**答案准确率同样带此噪声**。
- **我如何应对**：立为全项目结论表述标准 —— **小于 1pp 的分数差异一律不做精读、不当作结论**。本报告所有结论的差异（+9.3pp / +14.1pp）都远大于噪声地板，方向可信；但**不应按百分点精确解读**，且每处结论都同时给出样本量。
- **验证路径**：对同一组 (问题, 检索块, 生成答案) 重复裁判 3 次，测一致率，给出精确噪声地板（需先让评测器保存生成答案，见 future work）。

### 局限二：同一评测集四轮迭代，存在过拟合风险

- **现象**：四级迭代（基线 → 茆书 → 混合检索 → prompt）**全部在同一批 282 条真实答疑上做**。prompt 尤其容易学到这批数据的语言习惯 —— 例如学生提问的口语化措辞、"这个题/这一步"的指代模式。
- **含义**：35.7% 这个数字**可能有偏**，它衡量的是"在这批数据上表现如何"，不完全等于"对新题表现如何"。
- **我如何应对**：不把它当作泛化性能的证据，在报告中显式标注；并把它列为**最高优先级 future work** —— 用老师新出的题（来源=构造，未参与任何调参）做 held-out 验证。
- **验证路径**：老师按薄弱章节出题（同时解决薄弱章节样本量小的问题）→ 建独立评测脚本 → 只跑一次，用结果决定是否推翻现有结论。

### 局限三：编造率 57–60%，根因在检索覆盖而非 prompt

- **现象**：改 prompt **前后**编造率都没变（统计 60% → 57%、数学 57% → 57%）。也就是说，"资料不够但硬答"在改 prompt 之前就是常态。
- **根因证据**：检索相关性分布里，**约七成的问题被判为「不足」**。模型经常处于「手上没有可用资料」的状态，只能靠自身知识作答。
- **含义**：想降低编造，靠调 prompt 措辞是无效的 —— 真正的杠杆是**提高语料覆盖 / 检索命中**（第 7 章假设检验尚未 OCR、贾书未处理，都属此列）。
- **这个指标本身的局限**：二元「有编造 / 无编造」判级把**「模型用自身知识答对」**和**「编造幻觉」**混为一谈。所以本报告的编造率 A/B 只证明了「硬答没变多」，**不等于「多答的都答对了」**。要区分二者，需要引入"答案是否正确"的独立校验。
